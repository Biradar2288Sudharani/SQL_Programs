Question 1: Explain your project.
"My project is a Face Recognition Attendance System developed using Python. The main objective is to automate student attendance 
using face recognition instead of manual attendance.
The application provides student registration where user details like ID, name, roll number, department, phone number, email, and address are stored.
After registration, the system captures multiple face images through the webcam and stores them for training.
I used OpenCV's LBPH Face Recognizer to train the model. During attendance, the webcam detects and recognizes students in real time, then automatically 
marks attendance in a CSV file and database.
I also integrated attendance analytics using Matplotlib to generate monthly and subject-wise attendance reports.
Additionally, I integrated the Twilio WhatsApp API to automatically send attendance notifications to parents. Students with attendance 
above 95% receive a congratulatory message, while those below 75% receive a warning message."

SECTION C: Python Core Concepts
16. What are Python's key features?
Python is interpreted, dynamically typed, and has simple, readable syntax. It supports multiple programming paradigms — procedural, object-oriented, 
and functional. It also has a huge standard library and third-party ecosystem, like Django and OpenCV, which I used directly in my projects.
17. What is the difference between a list and a tuple?
A list is mutable — I can change, add, or remove elements after creation. A tuple is immutable — once created, its values can't change. 
I generally use tuples for fixed data, like coordinates, and lists for data that changes, like a list of attendance records.
18. What is the difference between deep copy and shallow copy?
A shallow copy creates a new object but copies references to the nested objects inside, so changes to nested data affect both copies.
A deep copy creates a completely independent copy, including nested objects, so changes don't affect the original.
19. What are Python decorators?
A decorator is a function that wraps another function to extend its behavior without modifying its actual code. 
For example, I could use a decorator to log every time an attendance-marking function is called, without changing the function itself.
**20. What are *args and kwargs?
*args lets a function accept any number of positional arguments, and **kwargs lets it accept any number of keyword arguments.
I use this when I want a function to be flexible about input, like a function that formats attendance data differently depending on optional parameters passed.
21. What is the difference between is and == in Python?
== checks if values are equal, while is checks if two variables point to the exact same object in memory. 
So two lists with the same content will be == but not necessarily is.
22. What are Python generators?
Generators let you iterate over data without loading everything into memory at once, using the yield keyword. 
They're useful when processing large datasets, like reading attendance records row by row instead of loading the whole file into memory.
23. What is a lambda function?
A lambda is a small anonymous function defined in a single line, usually used for short operations like sorting or filtering. 
For example, I could use a lambda to sort a list of students by attendance percentage.
24. Explain exception handling in Python.
Python uses try, except, else, and finally blocks. I put risky code — like database queries or file operations — inside try, catch specific errors in except, 
and use finally for cleanup code, like closing a database connection, which always needs to run.
25. What is the difference between __init__ and __new__?
__new__ actually creates the object, while __init__ initializes it after creation. In practice, I use __init__ almost always;
__new__ is rarely overridden unless doing something advanced like implementing a singleton.
26. What are Python's data structures you've commonly used?
Lists, dictionaries, sets, and tuples. In my attendance project, I used dictionaries a lot to map student IDs to their attendance data because lookups by key are fast.
27. What is list comprehension? Give an example.
It's a concise way to create lists. For example, [s for s in students if s.attendance > 75] gives me all students with attendance above 75% in a single readable line instead of a multi-line loop.
28. What is the Global Interpreter Lock (GIL)?
The GIL is a mutex in CPython that allows only one thread to execute Python bytecode at a time, even on multi-core systems. It means true parallel CPU-bound execution needs multiprocessing instead of threading in Python.
29. Difference between multithreading and multiprocessing?
Multithreading runs multiple threads within the same process and is good for I/O-bound tasks, like waiting on API calls. Multiprocessing runs separate processes with separate memory, better for CPU-heavy tasks, since it bypasses the GIL.
30. What is PEP8?
PEP8 is Python's official style guide — covering naming conventions, indentation, and code layout — that helps keep code consistent and readable across teams.

SECTION D: Object-Oriented Programming
31. What are the four pillars of OOP?
Encapsulation, Inheritance, Polymorphism, and Abstraction. In my attendance system, I used classes like Student and AttendanceManager to encapsulate data and behavior together.
32. What is inheritance? Give a practical example from your work.
Inheritance lets one class reuse and extend another class's behavior. For example, if I had a base User class, I could create a Student class that inherits from it and adds attendance-specific fields.
33. What is polymorphism?
Polymorphism means the same method name behaves differently depending on the object calling it. For example, a generate_report() method could behave differently for a MonthlyReport class versus a SubjectWiseReport class.
34. What is encapsulation, and why is it useful?
Encapsulation means bundling data and methods together and restricting direct access to some of an object's components, usually using private/protected attributes. It protects the internal state — for instance, keeping a student's attendance count private and only modifiable through a controlled method, so it can't be updated incorrectly from outside the class.
35. What is abstraction?
Abstraction means hiding complex implementation details and exposing only what's necessary. For example, I don't need to know how OpenCV internally detects a face — I just call detectMultiScale() and get the result.
36. What is method overriding vs method overloading?
Overriding means a child class provides its own version of a method already defined in the parent class. Python doesn't support traditional method overloading (same method name, different parameters) like Java, but similar behavior can be achieved using default arguments or *args.
37. What is a class variable vs an instance variable?
A class variable is shared across all instances of a class, while an instance variable is unique to each object. For example, a school_name could be a class variable shared by all students, while student_id would be unique per instance.
38. What are static methods and class methods?
A static method doesn't access instance or class data — it behaves like a regular function inside a class, used with @staticmethod. A class method receives the class itself as the first argument (cls) and can modify class-level state, used with @classmethod.
39. What is a constructor in Python?
The __init__ method acts as the constructor — it runs automatically when an object is created and is used to initialize instance attributes.
40. Can you explain composition vs inheritance?
Inheritance means "is-a" relationship — a Student is a type of User. Composition means "has-a" relationship — a Report class might contain a Student object rather than inheriting from it. I generally prefer composition when the relationship isn't strictly hierarchical.
SECTION E: Django Framework
41. What is Django, and why did you choose it for your internship project?
Django is a high-level Python web framework that follows the MVT (Model-View-Template) pattern and comes with a lot of built-in features like an ORM, admin panel, and authentication system. I used it at LiteCode because it let us build and deploy web applications quickly with secure defaults already in place.
42. Explain the MVT architecture in Django.
Model handles the data and database structure, View contains the business logic and decides what data to send, and Template handles how that data is displayed to the user. Django's URL dispatcher connects incoming requests to the right view.
43. What is Django ORM?
Django ORM lets you interact with the database using Python classes and objects instead of writing raw SQL. For example, Student.objects.filter(attendance__gte=75) instead of writing a SQL query manually.
44. How does Django handle authentication? You mentioned using django-allauth — explain that.
Django provides a built-in authentication system for login, logout, and password management. For more advanced needs, I used django-allauth in my internship project to add sign-up, login, email verification, and Google OAuth login, which saved us from writing that logic from scratch and gave us tested, secure flows.
45. What is Django OAuth login, and how does the flow work (Google OAuth specifically)?
When a user clicks "Login with Google," they're redirected to Google's consent screen. After they approve, Google redirects back to our app's callback URL with an authorization code. django-allauth exchanges that code for user info and access tokens, then creates or logs in the corresponding user in our database.
46. What are Django migrations?
Migrations are Django's way of propagating changes made to models (like adding a new field) into the actual database schema. I run makemigrations to generate the migration file and migrate to apply it to the database.
47. What is the Django admin panel, and how did you use it?
Django provides an auto-generated admin interface to manage database records without writing custom UI. During my internship, we used it to quickly view and manage user data and application content while the actual customer-facing UI was being built.
48. Explain Django's request-response cycle.
A request comes in, Django's URL dispatcher matches it to a view based on urls.py, the view processes the logic (often interacting with models), and returns a response — usually a rendered template or JSON data — back to the client.
49. What is a Django middleware?
Middleware is a layer that processes requests and responses globally before they reach the view or after the view returns them — for example, handling authentication checks or logging on every request.
50. How did you deploy your Django project on GoDaddy servers?
I configured the server with the required Python environment, set up the WSGI/Gunicorn configuration, connected the domain, configured static file serving, and set environment variables like DEBUG=False and allowed hosts for production settings.
51. What is the difference between DEBUG=True and DEBUG=False in Django settings?
DEBUG=True shows detailed error pages, useful during development but a security risk in production because it can expose sensitive information. DEBUG=False is used in production and requires proper ALLOWED_HOSTS and custom error pages configured.
52. What are Django signals?
Signals let certain senders notify other parts of the app when an action happens — for example, automatically creating a user profile right after a User object is saved, using the post_save signal.
53. How do you handle CRUD operations in Django?
I use Django's ORM methods — objects.create() for Create, objects.filter()/get() for Read, save() after modifying an instance for Update, and .delete() for Delete — usually wired up through views and forms or REST API endpoints.
54. What is a Django Form vs a ModelForm?
A regular Form is defined manually field by field, while a ModelForm is automatically generated based on a model, saving time when the form maps directly to database fields — which is what I used for CRUD operations in my internship project.
55. How do you manage static and media files in Django during deployment?
Static files (CSS, JS) are collected using collectstatic and served via a web server or CDN in production, while media files (user uploads) are stored separately, often with proper MEDIA_URL/MEDIA_ROOT settings and sometimes cloud storage for scalability.
SECTION F: REST APIs
56. What is a REST API?
REST is an architectural style for designing networked applications using standard HTTP methods — GET, POST, PUT, DELETE — to perform operations on resources, typically exchanging data in JSON format.
57. What HTTP methods have you used, and what do they do?
GET to retrieve data, POST to create new data, PUT/PATCH to update existing data, and DELETE to remove data. I used these while building and testing APIs during both my internship and the Smart Campaign Solutions work.
58. How do you test APIs? You mentioned Postman.
I use Postman to send requests to an endpoint with different methods and payloads, check the response status codes and body, and verify the API behaves as expected. I also test edge cases, like missing fields or invalid data, to make sure error handling works.
59. What is the difference between PUT and PATCH?
PUT typically replaces the entire resource, while PATCH updates only the specific fields provided, without touching the rest of the resource.
60. What are HTTP status codes, and can you name a few?
They indicate the result of an HTTP request. 200 means success, 201 means created, 400 means bad request, 401 means unauthorized, 404 means not found, and 500 means internal server error.
61. What is a webhook, and how did you use it in your work?
A webhook is a way for one application to automatically notify another application in real time when an event happens, by sending an HTTP request to a configured URL. At Smart Campaign Solutions, I integrated webhooks to exchange data between WhatsApp automation tools and other business applications whenever a new message or event occurred.
62. How do you secure a REST API?
Common methods include token-based authentication (like JWT), API keys, HTTPS to encrypt data in transit, and validating/sanitizing all input to prevent injection attacks.
63. What is JSON, and why is it commonly used in APIs?
JSON (JavaScript Object Notation) is a lightweight, human-readable data format used to exchange data between a client and server. It's widely used because it's easy to parse in almost every programming language.
64. What is API rate limiting, and why is it important?
Rate limiting restricts how many requests a client can make in a given time period, protecting the server from being overwhelmed and preventing abuse.
65. Explain how you integrated the Twilio WhatsApp API in your attendance project.
I used Twilio's WhatsApp API to send automated attendance notifications to parents. After marking attendance, my system triggered an API call to Twilio with the parent's number and a message template, and Twilio handled delivering it over WhatsApp.
SECTION G: Databases (MySQL)
66. Why did you choose MySQL for your projects?
MySQL is a reliable, widely-used relational database that integrates well with Python and Django, has strong community support, and was a good fit for structured data like student records and attendance logs.
67. What is normalization, and why is it important?
Normalization is organizing database tables to reduce data redundancy and improve data integrity, typically by splitting data into related tables and using foreign keys, rather than repeating data across rows.
68. What is a primary key vs a foreign key?
A primary key uniquely identifies each record in a table, like a student_id. A foreign key is a field in one table that references the primary key of another table, linking related data — for example, linking an attendance record to a specific student.
69. What are SQL joins? Name the types.
Joins combine rows from two or more tables based on a related column. Types include INNER JOIN (only matching rows), LEFT JOIN (all rows from the left table plus matches), RIGHT JOIN, and FULL OUTER JOIN.
70. How did you use MySQL in your Face Recognition Attendance System?
I stored student details, face encoding data, and attendance records in MySQL tables. When attendance was marked, a new record was inserted with the student ID, date, and time, which I then queried to generate monthly and subject-wise reports.
71. What is indexing in databases, and why does it matter?
An index speeds up data retrieval by creating a data structure that allows the database to find rows faster, similar to an index in a book — very useful when tables grow large, like attendance logs over months.
72. What is the difference between DELETE, TRUNCATE, and DROP?
DELETE removes specific rows and can be rolled back if in a transaction. TRUNCATE removes all rows quickly but keeps the table structure. DROP removes the entire table, including its structure.
73. How do you handle database connections securely in a Python/Django app?
I avoid hardcoding credentials in code — using environment variables or a .env file instead — and use Django's built-in database connection handling, which manages connection pooling and closes connections properly.
74. What is a transaction in a database?
A transaction is a group of operations executed as a single unit — either all succeed or none do — which keeps data consistent, for example when updating attendance and a related summary count together.
75. How would you optimize a slow SQL query?
I'd check if proper indexes exist on the columns used in WHERE/JOIN clauses, avoid SELECT * and only fetch needed columns, and analyze the query execution plan to spot bottlenecks.
SECTION H: Git & Version Control
76. How did you use Git and GitHub during your internship?
I used Git for version control — creating branches for new features, committing changes with clear messages, and pushing to GitHub. This let the team work in parallel and review each other's code before merging.
77. What is the difference between git merge and git rebase?
Merge combines two branches and creates a new merge commit, preserving full history. Rebase moves your branch's commits on top of another branch's latest commits, creating a cleaner, linear history.
78. What is a merge conflict, and how do you resolve it?
A merge conflict happens when two branches have changed the same part of a file differently. I resolve it by manually reviewing the conflicting sections Git highlights, choosing or combining the correct changes, then committing the resolved file.
79. What is the difference between git pull and git fetch?
git fetch downloads changes from the remote without merging them into your local branch. git pull does a fetch and then automatically merges those changes into your current branch.
80. How do you revert a commit that's already been pushed?
I'd use git revert <commit>, which creates a new commit that undoes the changes, keeping history intact — safer than git reset on shared branches.
SECTION I: Testing
81. What is unit testing, and why is it important?
Unit testing checks individual pieces of code — like a single function or method — in isolation to confirm they work correctly. It catches bugs early and gives confidence when refactoring code later.
82. What testing have you done in your projects?
I used unit tests to verify core logic, like attendance calculations, and used Postman extensively to test API endpoints — checking correct responses, status codes, and handling of invalid input.
83. What is the difference between unit testing and integration testing?
Unit testing checks a single function or module in isolation, often using mock data. Integration testing checks how multiple modules or systems work together, such as verifying that the API correctly writes to the database and returns the right response.
84. How do you test an API that depends on an external service, like Twilio or WhatsApp?
I'd use mock responses or Postman with test/sandbox credentials provided by the service, so I can verify my code's behavior without depending on the real service or incurring costs during testing.
SECTION J: Deep Dive — Face Recognition Attendance System
85. Walk me through how your Face Recognition Attendance System works end-to-end.
The system captures a student's face using a webcam through OpenCV, matches it against previously stored face encodings, and if a match is found, automatically logs their attendance with a timestamp into MySQL. I built the interface using Tkinter, so staff could interact with it easily — capturing new student faces, viewing records, and generating reports.
86. How does face recognition actually work technically?
First, faces are detected in an image or video frame. Then facial features are converted into a numerical encoding (a vector representation). To recognize someone, the system compares the new face's encoding with stored encodings and finds the closest match within a similarity threshold.
87. What challenges did you face while building this project?
Handling lighting variations and different angles was tricky since it affected recognition accuracy. I also had to make sure duplicate attendance wasn't marked if a student stayed in front of the camera too long, so I added logic to prevent re-marking attendance within the same session.
88. Why did you choose Tkinter for the interface instead of a web framework?
Since this was a standalone desktop tool meant for use in a classroom/lab setting without needing internet-based access, Tkinter was a simple, fast way to build a functional GUI without the overhead of a full web stack.
89. How did you generate attendance reports and charts?
I used Matplotlib to visualize attendance data — pulling records from MySQL and plotting monthly, overall, and subject-wise attendance trends so staff could quickly spot patterns like frequently absent students.
90. How does the timetable module calculate subject-wise attendance?
It cross-references the class schedule with attendance records, so instead of just an overall percentage, it calculates attendance specific to each subject based on which classes were actually scheduled and attended.
91. How would you scale this project if it needed to handle thousands of students across multiple classrooms?
I'd move from a desktop Tkinter app to a web-based system with a proper backend (like Django), use a more scalable database setup, possibly separate the face-matching logic into its own service, and consider cloud storage for face data and images instead of local storage.
92. How do you ensure the security/privacy of students' facial data?
Facial data is sensitive, so I'd store encodings rather than raw images where possible, restrict database access, and ensure only authorized staff accounts can access or export student data.
93. Why MySQL instead of a NoSQL database for this project?
The data was structured and relational — students, attendance records, and subjects all having clear relationships — so a relational database like MySQL was a natural fit for consistent queries and reporting.
94. What would you improve if you rebuilt this project today?
I'd add proper user authentication for staff, move it to a web-based interface for broader accessibility, and add better error handling and logging for real-world reliability.

## SECTION J: Deep Dive — Face Recognition Attendance System

**85. Walk me through how your Face Recognition Attendance System works end-to-end.**
> The system captures a student's face using a webcam through OpenCV, matches it against previously stored face encodings,
 and if a match is found, automatically logs their attendance with a timestamp into MySQL. I built the interface using Tkinter, 
so staff could interact with it easily — capturing new student faces, viewing records, and generating reports.

**86. How does face recognition actually work technically?**
> First, faces are detected in an image or video frame. Then facial features are converted into a numerical encoding (a vector representation). 
To recognize someone, the system compares the new face's encoding with stored encodings and finds the closest match within a similarity threshold.

**87. What challenges did you face while building this project?**
> Handling lighting variations and different angles was tricky since it affected recognition accuracy. 
I also had to make sure duplicate attendance wasn't marked if a student stayed in front of the camera too long, 
so I added logic to prevent re-marking attendance within the same session.

**88. Why did you choose Tkinter for the interface instead of a web framework?**
> Since this was a standalone desktop tool meant for use in a classroom/lab setting without needing internet-based access, 
Tkinter was a simple, fast way to build a functional GUI without the overhead of a full web stack.

**89. How did you generate attendance reports and charts?**
> I used Matplotlib to visualize attendance data — pulling records from MySQL and plotting monthly, overall, 
and subject-wise attendance trends so staff could quickly spot patterns like frequently absent students.

**90. How does the timetable module calculate subject-wise attendance?**
> It cross-references the class schedule with attendance records, so instead of just an overall percentage, 
it calculates attendance specific to each subject based on which classes were actually scheduled and attended.

**91. How would you scale this project if it needed to handle thousands of students across multiple classrooms?**
> I'd move from a desktop Tkinter app to a web-based system with a proper backend (like Django), use a more scalable database setup, 
possibly separate the face-matching logic into its own service, and consider cloud storage for face data and images instead of local storage.

**92. How do you ensure the security/privacy of students' facial data?**
> Facial data is sensitive, so I'd store encodings rather than raw images where possible, 
restrict database access, and ensure only authorized staff accounts can access or export student data.

**93. Why MySQL instead of a NoSQL database for this project?**
> The data was structured and relational — students, attendance records, and subjects all having clear relationships — 
so a relational database like MySQL was a natural fit for consistent queries and reporting.

**94. What would you improve if you rebuilt this project today?**
> I'd add proper user authentication for staff, move it to a web-based interface for broader accessibility, 
and add better error handling and logging for real-world reliability.

## SECTION N: Deep "Why / How Would You Improve" — Flask

**111. You've used Flask — why would someone choose Flask over Django for a project?**
> Flask is a micro-framework — it gives you routing and basic request handling but doesn't force a structure like Django's ORM, 
admin panel, or app layout. I'd choose Flask when I need something lightweight and flexible, 
like a small API service or a microservice, where I don't need Django's full package and want to pick my own database layer, auth method, and libraries.

**112. Why would you NOT use Flask for a large enterprise application?**
> Because Flask gives you freedom but not structure — as the app grows, you have to manually add things Django gives for free, 
like ORM, admin panel, built-in auth, and migrations. Without discipline, 
a large Flask codebase can become inconsistent across teams since everyone can structure things differently.

**113. How is routing handled in Flask, and why is it designed that way?**
> Flask uses decorators like `@app.route('/students')` to map a URL directly to a Python function. 
It's designed this way to keep routing close to the logic it triggers, making small apps very readable — 
you can see the URL and its handler in one place instead of a separate routing file.

**114. How would you structure a Flask project so it doesn't turn into a mess as it grows?**
> I'd use application factories and Blueprints — splitting the app into modules (like `auth`, `students`, `attendance`) each with their own routes, 
models, and templates, instead of putting everything in one `app.py` file. This makes it maintainable as the codebase scales.

**115. Flask doesn't have a built-in ORM like Django — how would you handle the database, and why?**
> I'd use SQLAlchemy, since it's the most mature ORM in the Flask ecosystem and integrates well through Flask-SQLAlchemy. 
I'd choose it over raw SQL queries because it gives me model-based access, migrations (via Alembic), 
and protection against SQL injection — while still being lighter than Django's full stack.

**116. How would you add authentication to a Flask app, and why not just write it from scratch?**
> I'd use Flask-Login or Flask-JWT-Extended depending on whether it's a session-based web app or a token-based API. 
I wouldn't write auth from scratch because security-critical code — password hashing, session handling, token expiry — is easy to get subtly wrong, 
and these libraries are already tested by the community.

**117. How do you handle configuration (like secret keys, DB URLs) in Flask, and why does it matter?**
> I'd keep config in environment variables or a `.env` file loaded via `python-dotenv`, rather than hardcoding them in `app.py`. 
This matters because hardcoded secrets can leak if the code is pushed to GitHub, and it lets me use different configs for development, 
testing, and production without changing code.

**118. How would you make a Flask API faster/more scalable in production?**
> I wouldn't run it with the built-in development server — I'd deploy it behind a production WSGI server like Gunicorn, 
put Nginx in front for load balancing and static file serving, and add caching (like Redis) for frequently requested data instead of hitting the database every time.

**119. What is Flask's application context and request context — why do they exist?**
> They exist because Flask needs to know which app/request it's currently handling when your code runs, especially since Flask apps can have multiple instances.
 The application context (`current_app`) gives access to app-level config, and the request context (`request`) gives access to the current incoming request's data — 
Flask pushes these automatically so your view functions can use global-like objects safely.

**120. How would you handle errors globally in a Flask app instead of repeating try/except everywhere?**
> I'd use Flask's `@app.errorhandler()` decorator to catch specific exceptions or status codes globally — for example, 
returning a consistent JSON error response for all 404s or validation errors — instead of duplicating error-handling logic in every view.

🐍 20 Important Python Coding Questions + How to Explain
1. Reverse a String ⭐⭐⭐
text = "python"

reverse = text[::-1]

print(reverse)
🎤 How to explain

“First, I store the string python in the variable text. Then I use Python slicing with [::-1]. The first two values are omitted, so the entire string is selected, and -1 means we move from right to left. Therefore, the string gets reversed.”

Output:

nohtyp
Follow-up

Why does [::-1] reverse the string?

“Because the slicing step is -1, Python traverses the sequence from the last element to the first.”

2. Check Whether a String Is Palindrome ⭐⭐⭐
text = "madam"

if text == text[::-1]:
    print("Palindrome")
else:
    print("Not Palindrome")
🎤 Explanation

“I first store the string. Then I reverse the string using slicing and compare it with the original string. If both are equal, it is a palindrome; otherwise it is not.”

Output:

Palindrome
3. Find Factorial of a Number ⭐⭐⭐
n = 5

factorial = 1

for i in range(1, n + 1):
    factorial = factorial * i

print(factorial)
🎤 Explanation

“I initialize factorial to 1 because multiplication should start from 1. Then the for loop runs from 1 to n. In every iteration, I multiply the current factorial value by i. For 5, the calculation becomes 1 × 2 × 3 × 4 × 5, which gives 120.”

Output:

120
Interview follow-up

Why n + 1?

“Because the upper limit of range() is exclusive, so I use n + 1 to include n.”

4. Fibonacci Series ⭐⭐⭐

    print(a, end=" ")

    a, b = b, a + b
🎤 Explanation

“I initialize the first two Fibonacci numbers as 0 and 1. In every iteration, I print a. Then I simultaneously update a to b and b to a + b. Python's multiple assignment allows me to update both variables in one statement.”

Output:

0 1 1 2 3 5 8
5. Check Prime Number ⭐⭐⭐
n = 17

if n <= 1:
    print("Not Prime")
else:
    for i in range(2, n):
        if n % i == 0:
            print("Not Prime")
            break
    else:
        print("Prime")
🎤 Explanation

“A prime number is greater than 1 and has only two factors: 1 and itself. So I first check whether the number is less than or equal to 1. Then I check whether any number from 2 to n-1 divides it completely. If n % i is zero, it has another factor and is not prime. If the loop completes without finding a divisor, it is prime.”

🔥 Interviewer may ask:

12. Sum of Digits ⭐⭐⭐
n = 12345

print(total)
🎤 Explanation

5 → 4 → 3 → 2 → 1

Result:

13. Reverse a Number ⭐⭐⭐

    n = n // 10

print(reverse)
🎤 Explanation

“I extract the last digit using % 10. Then I shift the existing reverse number one position to the left by multiplying it by 10 and add the extracted digit. Finally, I remove the last digit from the original number using // 10.”

Output:

4321
14. Check Armstrong Number ⭐⭐⭐
n = 153

total = 0
temp = n

while temp > 0:
    digit = temp % 10
    total += digit ** 3
    temp = temp // 10

if total == n:
    print("Armstrong")
else:
    print("Not Armstrong")
🎤 Explanation

“I store the original number in n and make a temporary copy because I need the original number for comparison later. I extract each digit using % 10, cube the digit, and add it to total. After processing all digits, I compare the calculated total with the original number.”

For 153:

1³ + 5³ + 3³
= 1 + 125 + 27
= 153

Therefore it is an Armstrong number.

19. Sort a List Without sort() ⭐⭐⭐⭐
numbers = [5, 2, 8, 1, 3]

for i in range(len(numbers)):
    for j in range(i + 1, len(numbers)):
        if numbers[i] > numbers[j]:
            numbers[i], numbers[j] = numbers[j], numbers[i]

print(numbers)
🎤 Explanation

“I compare each element with the elements after it. If the current element is greater than a later element, I swap them. By repeatedly doing this, smaller values move toward the beginning of the list.”

[1, 2, 3, 5, 8]

This demonstrates your understanding of sorting logic and nested loops.

🚀 PVKL Python Developer — Important API Questions
⭐ 1. What is an API?

Answer:

API stands for Application Programming Interface. It allows two different software applications to communicate with each other and exchange data.

Example:

Frontend → API → Backend → Database
⭐ 2. What is a REST API?

Answer:

REST stands for Representational State Transfer. A REST API is an API that follows REST principles and uses HTTP methods such as GET, POST, PUT, PATCH and DELETE to work with resources.

Example:

GET    /users
POST   /users
GET    /users/10
PUT    /users/10
DELETE /users/10
⭐ 3. What are HTTP methods?

Know these very clearly:

Method	Purpose
GET	Retrieve data
POST	Create data
PUT	Completely update data
PATCH	Partially update data
DELETE	Delete data
Interview example:
GET /products/10

Gets product 10.

POST /products

Creates a new product.

⭐ 4. GET vs POST

GET:

Used to retrieve data
Parameters may appear in URL
Should not modify server data

POST:

Used to create/send data
Data is generally sent in request body
Commonly changes server-side state

Example:

GET /users/10
POST /users

with:

{
    "name": "Sudha",
    "email": "sudha@example.com"
}
⭐ 5. PUT vs PATCH

This is a very common interview question.

PUT

Used to replace/update the complete resource.

PATCH

Used to update only specific fields.

Example:

PUT /users/10

You might send the complete user representation.

PATCH /users/10

You might send only:

{
    "email": "new@example.com"
}
⭐ 6. What is a HTTP status code?

A status code tells the client what happened with the request.

Memorize these:

200 → OK
201 → Created
204 → No Content

400 → Bad Request
401 → Unauthorized
403 → Forbidden
404 → Not Found
405 → Method Not Allowed

500 → Internal Server Error
502 → Bad Gateway
503 → Service Unavailable
🔥 Especially remember:

401 vs 403

401 → Authentication is missing/invalid.
403 → The client is authenticated but doesn't have permission.

Answer:

JSON stands for JavaScript Object Notation. It is a lightweight data-interchange format commonly used for sending and receiving data through APIs.

{

⭐ 15. What is JWT?

JWT = JSON Web Token.

It is commonly used for authentication between clients and servers.

Typical flow:

Login
   ↓
Server validates credentials
   ↓
Server generates JWT
   ↓
Client stores token
   ↓
Client sends token with future requests

Example:

Authorization: Bearer <JWT_TOKEN>
⭐ 16. What is an API endpoint?

An endpoint is a specific URL through which a client accesses a particular resource/function.

Example:

/users
/products
/orders

More specifically:

GET /users/10

is an endpoint for retrieving user 10.

⭐ 17. What is CRUD?

This is very important for backend interviews.

C → Create
R → Read
U → Update
D → Delete

Typical REST mapping:

Create → POST
Read   → GET
Update → PUT/PATCH
Delete → DELETE
⭐ 18. What is idempotency?

This is a slightly advanced but impressive question.

An operation is idempotent when making the same request multiple times produces the same intended final state.

For example, a properly designed:

PUT /users/10

with the same complete representation should leave the resource in the same state whether sent once or multiple times.

GET, PUT, and DELETE are generally considered idempotent by HTTP semantics; POST generally isn't.

⭐ 19. What is API pagination?

Suppose your database contains:

1,000,000 users

You shouldn't normally return all of them in one API response.

Instead:

GET /users?page=1&limit=20

Response:

{
    "page": 1,
    "limit": 20,
    "total": 1000000,
    "results": [...]
}

This is pagination.

⭐ 20. What is API rate limiting?

Rate limiting restricts how many requests a client can make within a specific period.

Example:

100 requests / minute

It helps protect the server from excessive traffic and abuse.

⭐ 22. What is a serializer?

Answer:

A serializer converts complex data such as Django model instances into JSON-compatible Python data that can be returned through an API. It can also validate incoming data.

Example:

from rest_framework import serializers

class UserSerializer(serializers.ModelSerializer):
    class Meta:
        model = User
        fields = "__all__"
⭐ 23. APIView vs ViewSet

Know the basic distinction.

APIView

Provides more explicit control over HTTP methods:

class UserAPIView(APIView):

    def get(self, request):
        ...

    def post(self, request):
        ...
ViewSet

Groups related CRUD operations into one class and works naturally with routers.

⭐ 24. What is Django ORM?

Django ORM allows us to interact with the database using Python objects and query expressions instead of writing SQL for every operation.

Example:

users = User.objects.filter(is_active=True)
⭐ 25. How would you debug a 500 API error?

Don't simply say:

Show your debugging process.

import requests

url = "https://api.example.com/users"

try:
    response = requests.get(url, timeout=5)
    response.raise_for_status()

    data = response.json()

    for user in data:
        print(user)

except requests.exceptions.RequestException as e:
    print("Error:", e)
