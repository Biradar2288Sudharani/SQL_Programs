🎯 MNC Technical HR Rapid Fire
Q1. What is Data?
Answer: Raw facts or information.

Q2. What is a Database?
Answer: An organized collection of related data stored electronically.

Q3. What is DBMS?
Answer: Software used to create, manage, retrieve, update, and delete data in a database.

Q4. What is RDBMS?
Answer: A DBMS that stores data in related tables and maintains relationships using keys.

Q5. What is SQL?
Answer: A language used to communicate with relational databases by creating, reading, updating, and deleting data.

Q1. Can a table exist without rows?
✅ Yes. A newly created table can have zero rows but still contain columns.

Q2. Can a table exist without columns?
❌ No. A table must have at least one column because columns define the structure of the data.

Q3. Is a row unique?
Not always. Unless a Primary Key or Unique Constraint is used, duplicate rows can exist.

Q4. What is the difference between a row and a record?
In SQL, they are generally the same. A record refers to the complete information about one entity, and it is stored as a row in the table.

Q1. Can a table have two Primary Keys?
No. A table can have only one Primary Key, although that Primary Key may consist of multiple columns (a composite primary key).

Q2. Can a table have multiple Foreign Keys?
Yes. A table can have multiple Foreign Keys referencing different tables or even the same table.

Q3. Difference between Primary Key and Unique Key?
Primary Key cannot contain NULL values and uniquely identifies each row.
Unique Key also prevents duplicate values, but in MySQL it generally allows one NULL value.

Q4. Why is a Foreign Key used?
To create relationships between tables and maintain referential integrity, ensuring that related data remains consistent.

Q5. Difference between Candidate Key and Super Key?
A Super Key is any combination of columns that uniquely identifies a row.
A Candidate Key is the smallest possible Super Key with no unnecessary columns.

🎯 MNC Technical HR Questions
Q1. What is a Constraint?
A constraint is a rule applied to a column to ensure data accuracy and integrity.

Q2. Why do we use NOT NULL?
To ensure that mandatory fields always contain a value.

Q3. Why use CHECK?
To restrict invalid data, such as ensuring age is at least 18 or salary is greater than zero.

Q4. Difference between CHAR and VARCHAR?
CHAR stores fixed-length strings and pads unused spaces.
VARCHAR stores variable-length strings and uses storage efficiently.

Q5. Why use DECIMAL instead of FLOAT for salary?
Because DECIMAL stores exact values without floating-point rounding errors, making it suitable for financial data.

Q1. Difference between DELETE and TRUNCATE?
DELETE removes selected rows (or all rows if no WHERE clause is used) and supports the WHERE clause.
TRUNCATE removes all rows quickly, does not support WHERE, and keeps the table structure.

Q2. Difference between DROP and TRUNCATE?
TRUNCATE removes only the data and keeps the table.
DROP removes both the table structure and all its data permanently.

Q3. Difference between CREATE and ALTER?
CREATE creates a new database object.
ALTER modifies the structure of an existing database object.

Q4. Why is WHERE important in UPDATE and DELETE?
Without a WHERE clause, UPDATE or DELETE affects every row in the table, which can lead to accidental data loss or incorrect updates.

Q5. Which SQL command is used most frequently in real projects?
SELECT is the most frequently used command because applications constantly retrieve data to display users, products, orders, reports, and other information.

Q1 - Why do we use WHERE?
Answer - WHERE filters rows based on a condition so that only the required data is returned.

Q2 - Does WHERE execute before SELECT?
Answer - Yes. SQL logically processes FROM, then WHERE, and finally SELECT.

Q3 - Can WHERE be used without SELECT?
Answer - Yes. It is commonly used with UPDATE and DELETE as well.
	Ex: UPDATE Employee
	SET salary = 60000
	WHERE emp_id = 101;
	DELETE FROM Employee
	WHERE department = 'HR';

Q4 - Can WHERE filter calculated values?
Answer - No. WHERE filters rows before grouping or aggregate calculations. For aggregated results, use HAVING.

Q5 - Does WHERE improve performance?
Answer - Yes. It reduces the number of rows processed. When combined with appropriate indexes, it can significantly improve query performance.

Q1 - Difference between AND and OR?
Answer - AND requires all conditions to be TRUE.
OR requires at least one condition to be TRUE.
Q2 - When do we use NOT?
Answer - NOT is used to exclude records that match a particular condition.

Q3 - Which operator has higher priority?
Answer - NOT has the highest priority, followed by AND, then OR.

Q4 - Can we use multiple AND conditions?
Answer - Yes. SQL allows multiple conditions joined by AND.
Example:
WHERE department='Python'
AND city='Pune'
AND salary>60000;

Q5 - Why should we use parentheses with AND and OR?
Answer - Parentheses make the intended logic explicit and avoid mistakes caused by SQL's operator precedence.

Q1 - Difference between IN and BETWEEN?

	BETWEEN checks whether a value falls within a continuous range.

Q2 - Difference between LIKE and = ?
Answer - = checks for an exact match.
	LIKE checks for pattern matches using wildcards.

Q3 - Difference between % and _ ?
Answer - %  : matches zero or more characters.
	 _  : matches exactly one character.

Q4 - Can BETWEEN work on DATE?
Answer - Yes. BETWEEN works with numbers, dates, and other comparable values.

Q5 - Can NOT be used with LIKE?
Answer - Yes.
Example
	SELECT *

Q1 - Difference between WHERE and HAVING?
Answer - WHERE filters individual rows before grouping, while HAVING filters grouped data after aggregation.

Q2 - Can HAVING work without GROUP BY?
Answer - Yes. If the query produces a single aggregated result, HAVING can filter that result.
Example: SELECT COUNT(*) FROM Employee HAVING COUNT(*) > 5;

Q3 - Can aggregate functions be used in WHERE?
Answer - No.
Incorrect: WHERE AVG(salary)>50000
Correct: HAVING AVG(salary)>50000

Q4 - Difference between COUNT(*) and COUNT(column)? 
Answer - COUNT(*) counts every row.
         COUNT(column) counts only rows where that column is not NULL.

Q5 - What is the difference between MAX() and ORDER BY DESC LIMIT 1?
Answer - MAX(salary) returns only the highest salary value.
         ORDER BY salary DESC LIMIT 1 returns the complete row (name, department, salary, etc.) of the highest-paid employee.

Q3 - Difference between COALESCE and CASE?

         CASE performs general conditional logic based on expressions.

Q1 What is LEFT JOIN?
Answer - LEFT JOIN returns all rows from the left table and matching rows from the right table. If no matching record exists,
         SQL fills the right-side columns with NULL.

Q2 When do you use LEFT JOIN?
Answer - When I need every record from the primary table, even if related data is missing.

Q3 - Can LEFT JOIN return NULL?
     Yes. - When no matching row exists in the right table.

Q4 - Can LEFT JOIN produce duplicate rows?
     Yes.- If one left-side row matches multiple right-side rows, multiple result rows are returned.

Q5 - Can LEFT JOIN be faster than INNER JOIN?
     Sometimes, but performance mainly depends on indexes, table sizes, and query execution plans rather than the join type alone.

Q1 - What is RIGHT JOIN?
Answer - RIGHT JOIN returns all rows from the right table and matching rows from the left table. If no matching row exists, the left-side columns become NULL.

Q2 - Why is RIGHT JOIN rarely used?
Answer - Because developers can achieve the same result by swapping the table order and using a LEFT JOIN, which is more commonly used and easier to read.

Q3 - Can RIGHT JOIN return NULL?
     Yes. - When no matching row exists in the left table.

Q4 - Can RIGHT JOIN be replaced?
     Yes. Swap table order. Use LEFT JOIN.

Q5 - Which JOIN do companies use more?
     LEFT JOIN.

Q1 - What is FULL OUTER JOIN?
FULL OUTER JOIN returns all matching and non-matching rows from both tables. Missing values are represented as NULL.

Q2 - When should we use FULL JOIN?
Answer - When we want complete data from both tables, including unmatched records.

Q3 - Does MySQL support FULL JOIN?
Answer - No. It is simulated using LEFT JOIN + UNION + RIGHT JOIN.

Q4 - Can FULL JOIN produce NULL values?
     Yes. - On both sides.

Q5 - Which databases support FULL JOIN?
     PostgreSQL, SQL Server, Oracle

Q1 - What is SELF JOIN?

Q1 - What is CROSS JOIN?
Answer - A CROSS JOIN returns the Cartesian Product of two tables by combining every row from the first table with every row from the second table.

Q2 - Does CROSS JOIN require an ON condition?
Answer - No.
         Unlike INNER, LEFT, and RIGHT JOIN, a CROSS JOIN does not use an ON clause.

Q3 - How many rows will be returned?
     Table A = 100 rows 
     Table B = 50 rows
     Answer - 100 × 50 = 5000 Rows

Q4 - When is CROSS JOIN used?
Answer - When every possible combination between two datasets is required, such as product variants, schedules, testing combinations, or matrix generation.

Q5 - Can CROSS JOIN become slow?
     Yes. - Because the number of rows grows multiplicatively.

Because unmatched employees produce:

NULL

and COUNT(column) doesn't count NULL.

PART 7 — RIGHT JOIN
What is RIGHT JOIN?

RIGHT JOIN returns:

ALL records from RIGHT table
+
matching records from LEFT table
Syntax
SELECT columns
FROM table1
RIGHT JOIN table2
ON table1.column = table2.column;
Memory trick
RIGHT JOIN
     ↓
RIGHT table = guaranteed
LEFT table = optional

Because Departments is on the right, all departments appear.

PART 8 — LEFT JOIN vs RIGHT JOIN

These two are often confusing.

LEFT JOIN
FROM Employees e
LEFT JOIN Departments d

means:

Keep ALL Employees
RIGHT JOIN
FROM Employees e
RIGHT JOIN Departments d

means:

Keep ALL Departments
Easy trick

Don't memorize the word LEFT.

Look at:

FROM A
LEFT JOIN B

A is guaranteed.

FROM A
RIGHT JOIN B

B is guaranteed.

PART 9 — FULL OUTER JOIN
What is FULL OUTER JOIN?

Returns:

Matching records
+
unmatched records from LEFT
+
unmatched records from RIGHT

Conceptually:

LEFT only
+
MATCH
+
RIGHT only
Syntax

In databases that support it:

SELECT *
FROM Employees e
FULL OUTER JOIN Departments d
ON e.Dept_ID = d.Dept_ID;
Important MySQL interview point

MySQL does not provide a native FULL OUTER JOIN syntax.

A common MySQL approach is:

SELECT *
FROM Employees e
LEFT JOIN Departments d
ON e.Dept_ID = d.Dept_ID

UNION

SELECT *
FROM Employees e
RIGHT JOIN Departments d
ON e.Dept_ID = d.Dept_ID;
PART 10 — CROSS JOIN
What is CROSS JOIN?

CROSS JOIN produces every possible combination of rows.

If:

Employees = 8 rows
Departments = 5 rows

Then:

8 × 5 = 40 rows
Syntax
SELECT *
FROM Employees
CROSS JOIN Departments;

There is normally no ON condition.

What is SELF JOIN?

A table joins with itself.

Useful for:

Employee → Manager

Employee → Mentor
Category → Parent Category

Our table contains:

Emp_ID
Manager_ID

So we can use the same Employees table twice.

PART 29 — The Most Important JOIN Patterns
Pattern 1 — Basic INNER JOIN
SELECT ...
FROM A
JOIN B
ON A.id = B.id;

Pattern 2 — LEFT JOIN
SELECT ...
FROM A
LEFT JOIN B
ON A.id = B.id;

Pattern 3 — Find unmatched records
SELECT ...
FROM A
LEFT JOIN B
ON A.id = B.id
WHERE B.id IS NULL;

⭐ Very important.

Pattern 4 — Multiple JOIN
SELECT ...
FROM A
JOIN B
ON A.id = B.a_id
JOIN C
ON B.id = C.b_id;

Pattern 5 — SELF JOIN
SELECT
    e.Name,
    m.Name
FROM Employees e
JOIN Employees m
ON e.Manager_ID = m.Emp_ID;

Pattern 6 — JOIN + GROUP BY
SELECT
    B.name,
    COUNT(A.id)
FROM A
JOIN B
ON A.b_id = B.id
GROUP BY B.name;

Pattern 7 — JOIN + HAVING
SELECT
    B.name,
    COUNT(A.id)
FROM A
JOIN B
ON A.b_id = B.id
GROUP BY B.name
HAVING COUNT(A.id) > 2;

Pattern 8 — JOIN + Aggregate
SELECT
    B.name,
    AVG(A.salary),
    MAX(A.salary),
    MIN(A.salary),
    SUM(A.salary)
FROM A
JOIN B
ON A.b_id = B.id
GROUP BY B.name;
