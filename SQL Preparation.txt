🎯 MNC Technical HR Rapid Fire
Q1. What is Data?
Answer: Raw facts or information.

Q2. What is a Database?
Answer: An organized collection of related data stored electronically.

Q3. What is DBMS?
Answer: Software used to create, manage, retrieve, update, and delete data in a database.

Q4. What is RDBMS?
Answer: A DBMS that stores data in related tables and maintains relationships using keys.

Q5. What is SQL?
Answer: A language used to communicate with relational databases by creating, reading, updating, and deleting data.

Q1. Can a table exist without rows?
✅ Yes. A newly created table can have zero rows but still contain columns.

Q2. Can a table exist without columns?
❌ No. A table must have at least one column because columns define the structure of the data.

Q3. Is a row unique?
Not always. Unless a Primary Key or Unique Constraint is used, duplicate rows can exist.

Q4. What is the difference between a row and a record?
In SQL, they are generally the same. A record refers to the complete information about one entity, and it is stored as a row in the table.

Q1. Can a table have two Primary Keys?
Answer:
No. A table can have only one Primary Key, although that Primary Key may consist of multiple columns (a composite primary key).

Q2. Can a table have multiple Foreign Keys?
Answer:
Yes. A table can have multiple Foreign Keys referencing different tables or even the same table.

Q3. Difference between Primary Key and Unique Key?
Answer:
Primary Key cannot contain NULL values and uniquely identifies each row.
Unique Key also prevents duplicate values, but in MySQL it generally allows one NULL value.

Q4. Why is a Foreign Key used?
Answer:
To create relationships between tables and maintain referential integrity, ensuring that related data remains consistent.

Q5. Difference between Candidate Key and Super Key?
Answer:
A Super Key is any combination of columns that uniquely identifies a row.
A Candidate Key is the smallest possible Super Key with no unnecessary columns.

🎯 MNC Technical HR Questions
Q1. What is a Constraint?
Answer:
A constraint is a rule applied to a column to ensure data accuracy and integrity.

Q2. Why do we use NOT NULL?
Answer:
To ensure that mandatory fields always contain a value.

Q3. Why use CHECK?
Answer:
To restrict invalid data, such as ensuring age is at least 18 or salary is greater than zero.

Q4. Difference between CHAR and VARCHAR?
Answer:
CHAR stores fixed-length strings and pads unused spaces.
VARCHAR stores variable-length strings and uses storage efficiently.

Q5. Why use DECIMAL instead of FLOAT for salary?
Answer:
Because DECIMAL stores exact values without floating-point rounding errors, making it suitable for financial data.

Q1. Difference between DELETE and TRUNCATE?
Answer:
DELETE removes selected rows (or all rows if no WHERE clause is used) and supports the WHERE clause.
TRUNCATE removes all rows quickly, does not support WHERE, and keeps the table structure.

Q2. Difference between DROP and TRUNCATE?
Answer:
TRUNCATE removes only the data and keeps the table.
DROP removes both the table structure and all its data permanently.

Q3. Difference between CREATE and ALTER?
Answer:
CREATE creates a new database object.
ALTER modifies the structure of an existing database object.

Q4. Why is WHERE important in UPDATE and DELETE?
Answer:
Without a WHERE clause, UPDATE or DELETE affects every row in the table, which can lead to accidental data loss or incorrect updates.

Q5. Which SQL command is used most frequently in real projects?
Answer:
SELECT is the most frequently used command because applications constantly retrieve data to display users, products, orders, reports, and other information.

Q1 - Why do we use WHERE?
Answer - WHERE filters rows based on a condition so that only the required data is returned.

Q2 - Does WHERE execute before SELECT?
Answer - Yes. SQL logically processes FROM, then WHERE, and finally SELECT.

Q3 - Can WHERE be used without SELECT?
Answer - Yes. It is commonly used with UPDATE and DELETE as well.
	Ex: UPDATE Employee
	SET salary = 60000
	WHERE emp_id = 101;
	DELETE FROM Employee
	WHERE department = 'HR';

Q4 - Can WHERE filter calculated values?
Answer - No. WHERE filters rows before grouping or aggregate calculations. For aggregated results, use HAVING.

Q5 - Does WHERE improve performance?
Answer - Yes. It reduces the number of rows processed. When combined with appropriate indexes, it can significantly improve query performance.

Q1 - Difference between AND and OR?
Answer - AND requires all conditions to be TRUE.
OR requires at least one condition to be TRUE.
Q2 - When do we use NOT?
Answer - NOT is used to exclude records that match a particular condition.

Q3 - Which operator has higher priority?
Answer - NOT has the highest priority, followed by AND, then OR.

Q4 - Can we use multiple AND conditions?
Answer - Yes. SQL allows multiple conditions joined by AND.
Example:
WHERE department='Python'
AND city='Pune'
AND salary>60000;

Q5 - Why should we use parentheses with AND and OR?
Answer - Parentheses make the intended logic explicit and avoid mistakes caused by SQL's operator precedence.

Q1 - Difference between IN and BETWEEN?
Answer - IN checks membership in a list.
	BETWEEN checks whether a value falls within a continuous range.

Q2 - Difference between LIKE and = ?
Answer - = checks for an exact match.
	LIKE checks for pattern matches using wildcards.

Q3 - Difference between % and _ ?
Answer - %  : matches zero or more characters.
	 _  : matches exactly one character.

Q4 - Can BETWEEN work on DATE?
Answer - Yes. BETWEEN works with numbers, dates, and other comparable values.

Q5 - Can NOT be used with LIKE?
Answer - Yes.
Example
	SELECT *
	FROM Employee
	WHERE name
	NOT LIKE 'S%';
	Returns names that do not start with S.

Q1 - Difference between ORDER BY and GROUP BY?
     ORDER BY sorts rows.
     GROUP BY groups rows before aggregation.

Q2 - Can ORDER BY work without LIMIT?
     Yes.

Q3 - Can LIMIT work without ORDER BY?
     Yes, but the returned rows may not be in a meaningful order because SQL tables do not guarantee row order unless you specify ORDER BY.

Q4 - Can DISTINCT remove duplicate rows?
     Yes, if every selected column has identical values.

Q5 - Which executes first?
    SELECT DISTINCT city FROM Employee ORDER BY city;

Q1 - Difference between WHERE and HAVING?
Answer - WHERE filters individual rows before grouping, while HAVING filters grouped data after aggregation.

Q2 - Can HAVING work without GROUP BY?
Answer - Yes. If the query produces a single aggregated result, HAVING can filter that result.
Example: SELECT COUNT(*) FROM Employee HAVING COUNT(*) > 5;

Q3 - Can aggregate functions be used in WHERE?
Answer - No.
Incorrect: WHERE AVG(salary)>50000
Correct: HAVING AVG(salary)>50000

Q4 - Difference between COUNT(*) and COUNT(column)? 
Answer - COUNT(*) counts every row.
         COUNT(column) counts only rows where that column is not NULL.

Q5 - What is the difference between MAX() and ORDER BY DESC LIMIT 1?
Answer - MAX(salary) returns only the highest salary value.
         ORDER BY salary DESC LIMIT 1 returns the complete row (name, department, salary, etc.) of the highest-paid employee.

Q1 - Difference between NULL and 0?
Answer - NULL means no value exists.
         0 is an actual numeric value.

Q2 - Can NULL equal NULL?
Answer - No. SQL treats comparisons involving NULL as UNKNOWN, so use IS NULL instead of =.

Q3 - Difference between COALESCE and CASE?
Answer - COALESCE replaces NULL by returning the first non-NULL value.
         CASE performs general conditional logic based on expressions.

Q4 - Can CASE be used in SELECT?
     Yes. Can CASE be used in ORDER BY?
     Yes. Can CASE be used in GROUP BY?
     Yes, when appropriate.

Q5 - Why is COALESCE better than displaying NULL?
     Because user-facing reports become more meaningful and easier to understand.
     Example: Instead of NULL Display No Manager Assigned

Q1 Why do we need JOIN?
A JOIN is used to retrieve related information stored in multiple normalized tables. It avoids data duplication and allows us to combine records using related keys.

Q2 Which key is commonly used in JOIN?
Primary Key and Foreign Key

Q3 Can we JOIN three tables? ->Yes.
   Four? -> Yes.
   Ten? -> Yes.
Companies join many tables in reporting and analytics queries.

Q4 Does JOIN permanently merge tables?
No. JOIN only combines data in the query result.

Q1 What is INNER JOIN?
Answer:INNER JOIN returns only the records that have matching values in both tables based on the join condition.

Q2 What happens if no match exists?
Answer: The row is excluded from the result set.

Q3 Can INNER JOIN produce duplicate rows?
Answer: Yes. If multiple matching rows exist in the second table, the joined result will contain multiple rows.

Q4 Which executes first: WHERE or JOIN?
Logical execution:

Q5 Why are joins preferred over storing everything in one table?
Answer: Joins support normalization, reduce data duplication, improve consistency, and make updates easier.

Q1 What is LEFT JOIN?
Answer - LEFT JOIN returns all rows from the left table and matching rows from the right table. If no matching record exists,
         SQL fills the right-side columns with NULL.

Q2 When do you use LEFT JOIN?
Answer - When I need every record from the primary table, even if related data is missing.

Q3 - Can LEFT JOIN return NULL?
     Yes. - When no matching row exists in the right table.

Q4 - Can LEFT JOIN produce duplicate rows?
     Yes.- If one left-side row matches multiple right-side rows, multiple result rows are returned.

Q5 - Can LEFT JOIN be faster than INNER JOIN?
     Sometimes, but performance mainly depends on indexes, table sizes, and query execution plans rather than the join type alone.

Q1 - What is RIGHT JOIN?
Answer - RIGHT JOIN returns all rows from the right table and matching rows from the left table. If no matching row exists, the left-side columns become NULL.

Q2 - Why is RIGHT JOIN rarely used?
Answer - Because developers can achieve the same result by swapping the table order and using a LEFT JOIN, which is more commonly used and easier to read.

Q3 - Can RIGHT JOIN return NULL?
     Yes. - When no matching row exists in the left table.

Q4 - Can RIGHT JOIN be replaced?
     Yes. Swap table order. Use LEFT JOIN.

Q5 - Which JOIN do companies use more?
     LEFT JOIN.

Q1 - What is FULL OUTER JOIN?
FULL OUTER JOIN returns all matching and non-matching rows from both tables. Missing values are represented as NULL.

Q2 - When should we use FULL JOIN?
Answer - When we want complete data from both tables, including unmatched records.

Q3 - Does MySQL support FULL JOIN?
Answer - No. It is simulated using LEFT JOIN + UNION + RIGHT JOIN.

Q4 - Can FULL JOIN produce NULL values?
     Yes. - On both sides.

Q5 - Which databases support FULL JOIN?
     PostgreSQL, SQL Server, Oracle

Q1 - What is SELF JOIN?
A SELF JOIN joins a table with itself using aliases. It is useful when rows in the same table are related, such as employee-manager relationships.

Q2 - Why are aliases mandatory?
Answer - Without aliases,
         SQL cannot distinguish between the two logical roles of the same table.

Q3 - Can SELF JOIN use LEFT JOIN?
     Yes.
     Example: Display All employees including those without managers.
              SELECT e.Name, m.Name AS Manager FROM Employee e LEFT JOIN Employee m ON e.Manager_ID = m.Emp_ID;

Q4 - Can SELF JOIN use INNER JOIN?
     Yes. - Only employees who have managers will appear.

Q5 - Where is SELF JOIN used in real projects?
Employee hierarchy
Category hierarchy
Folder structure
Family tree
Referral systems
Organizational charts

Q1 - What is CROSS JOIN?
Answer - A CROSS JOIN returns the Cartesian Product of two tables by combining every row from the first table with every row from the second table.

Q2 - Does CROSS JOIN require an ON condition?
Answer - No.
         Unlike INNER, LEFT, and RIGHT JOIN, a CROSS JOIN does not use an ON clause.

Q3 - How many rows will be returned?
     Table A = 100 rows 
     Table B = 50 rows
     Answer - 100 × 50 = 5000 Rows

Q4 - When is CROSS JOIN used?
Answer - When every possible combination between two datasets is required, such as product variants, schedules, testing combinations, or matrix generation.

Q5 - Can CROSS JOIN become slow?
     Yes. - Because the number of rows grows multiplicatively.

Q1 - What is a Subquery?
Answer - A Subquery is an SQL query written inside another SQL query. The inner query executes first and its result is used by the outer query.

Q2 - Which query executes first?
Answer - The inner query executes first.

Q3 - Can a Subquery return multiple rows?
     Yes. - Different types of Subqueries return one row, multiple rows, or multiple columns.

Q4 - Can a Subquery be used in SELECT?
     Yes.
     Example - SELECT Name,(SELECT AVG(Salary) FROM Employee ) AS Average_Salary FROM Employee;

Q5 - Where can Subqueries be used?
They can appear in:
SELECT
WHERE
FROM
HAVING
INSERT
UPDATE
DELETE

Q1 - What is a Scalar Subquery?
Answer - A Scalar Subquery is a subquery that returns exactly one row and one column, producing a single value that can be used anywhere a single value is expected.

Q2 - How many values can a Scalar Subquery return?
     Exactly one value.

Q3 - Can it return NULL?
     Yes.- If no rows satisfy the condition, many aggregate functions (except COUNT) can return NULL.

Q4 - Can it return multiple rows?
     No. - If a scalar subquery returns multiple rows where only one value is expected, the query fails.

Q5 - Why is AVG() commonly used in Scalar Subqueries?
     Because AVG() returns a single computed value.

Q1 - What is a Multi-row Subquery?
Answer - A Multi-row Subquery returns multiple rows and is typically used with operators like IN, ANY, or ALL.

Q2 - Why can't "=" be used?
Answer - Because "=" expects only one value.
         Multi-row Subqueries return multiple values.

Q3 - Which operator is commonly used?
Answer - IN

Q4 - Can AVG() create a Multi-row Subquery?
     No. - AVG() returns one value. That is Scalar.

Q5 - Which executes first?
     Always Subquery. Then Outer Query.

Q1 - What is a Correlated Subquery?
Answer - A Correlated Subquery is a subquery that references columns from the outer query. It executes once for each row processed by the outer query.

Q2 - What is the difference between a Normal Subquery and a Correlated Subquery?
     Normal	        Correlated
     Runs once	        Runs for every row
     Independent	Depends on outer query
     Usually faster	Can be slower on large tables

Q3 - Why can Correlated Subqueries be slow?
Answer: - Because the inner query executes repeatedly for every row of the outer query.

Q4 - Can a Correlated Subquery return multiple rows?
Yes, depending on the operator (EXISTS, IN, etc.), but many correlated subqueries are designed to return one value for each outer row.

Q5 - Can Correlated Subqueries be replaced?
     Yes. - Developers often replace them with: JOINs, Window Functions, CTEs to improve readability and performance.

Q1 - What is EXISTS?
Answer- EXISTS is an SQL operator that returns TRUE if the subquery returns at least one row; otherwise, it returns FALSE.

Q2 - What does EXISTS return?
Answer - Only TRUE or FALSE, It does not return the subquery data.

Q3 - Can EXISTS use SELECT *?
     Yes. - Database ignores the selected columns. It only checks Whether rows exist.

Q4 - Difference between EXISTS and IN?
     EXISTS	                                		IN
     Checks existence	                       		        Checks membership in a list
     Often efficient for correlated lookups		        Good for matching sets of values
     Stops after finding a qualifying row for the outer record	Behavior depends on optimizer and query plan

Q5 - What is NOT EXISTS?
Answer - Returns rows only when the subquery returns zero rows.

Q1 - What is ANY?
Answer- ANY returns TRUE if the comparison is true for at least one value returned by the subquery.

Q2 - What is ALL?
Answer - ALL returns TRUE only if the comparison is true for every value returned by the subquery.

Q3 - Difference?
	ANY					ALL
	At least one comparison must be TRUE	Every comparison must be TRUE
	Less strict				More strict

Q4 - Which is more restrictive?
     ✅ ALL - Because every comparison must succeed.

Q5 - Can ANY and ALL work with <, >, =, <=, >=, <>?
     Yes. - They work with comparison operators.

Q1 - Difference between UNION and UNION ALL?
Answer - UNION removes duplicate rows, whereas UNION ALL returns all rows including duplicates.

Q2 - Which is faster?
Answer - ✅ UNION ALL -> Because it doesn't perform duplicate elimination.

Q3 - Can UNION combine different numbers of columns?
     No. -> The SELECT statements must return the same number of columns.

Q4 - Can data types differ?
     Ideally, corresponding columns should have compatible data types.

Q5 - Does UNION sort data?
UNION performs duplicate elimination, which may involve sorting or hashing depending on the database engine. 
Do not rely on UNION to return rows in a specific order. If you need ordering, always use: ORDER BY, at the end of the UNION query.

Q1 - What is a Stored Procedure?
Answer - A Stored Procedure is a reusable program stored inside the database that contains SQL statements and procedural logic. 
	 It can accept parameters and execute multiple database operations efficiently.

Q2 - Why do companies use Stored Procedures?
Answer - Reusability
	 Security
	 Reduced network calls
	 Centralized business logic
	 Easier maintenance

Q3 - Can Stored Procedures accept parameters?
     Yes. - Input parameters are commonly supported, and some databases also support output parameters.

Q4 - Can Procedures return data?
     Yes. - They can return result sets and, depending on the database, output parameters.

Q5 - Can Procedures contain loops?
     Yes. - Most enterprise databases support procedural control structures like IF, WHILE, and loops.

✅ Simple Definition

A Window Function performs calculations across a set of rows without reducing the number of rows.

A Window Function performs aggregate or ranking calculations over a defined window (set of rows) while keeping every individual row in the result.
